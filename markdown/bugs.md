# 已解决

### 1. [2026-10-06] 修正 Ego-Exo4D 与 Ego4D 数据集规模及文档链接陈旧问题

- **引入/发现日期**: 2026-10-06
- **修复日期**: 2026-10-06
- **关联文件**: `README.md`

#### 根因分析
1. 原 `README.md` 中 Ego-Exo4D 条目描述为“覆盖熟练人类活动（约 116 小时）”，该数据为早期子集或局部标注工时统计，与官方正式发布的完整规模（约 1,286 小时）不符，容易误导读者以为其体量较小。
2. 经典数据集列表中的 Ego4D 仍沿用旧版 v1 的 3,025 小时及旧下载页 `ego4d.dev`，未反映当前扩展至约 3,670 小时的完整体量，亦缺少官方文档页、专有 CLI 下载库与 48 小时 AWS 凭证流程提示。

#### 修复逻辑
1. 更新 `Ego-Exo4D` 描述为全量约 1,286 小时，并明确标注头戴视角来自 Meta Project Aria 传感器眼镜，外部多机位同步录制。
2. 更新 `Ego4D` 规模为约 3,670 小时（保留原 v1 3,025 小时说明以供对照），补齐官方文档（`ego4d-data.org/docs/`）、专用 CLI 工具（`facebookresearch/Ego4d`）以及学术协议审批周期说明。
3. 在常用官方入口小节全面核验各数据集官方链接与可访问性，确保所有引用站点均返回 HTTP 200。

#### 反模式避坑准则
- 引用大型数据集时切忌使用早期宣传稿或单任务子集数据代表整个基准全貌。
- 涉及需凭证授权的 TB/PB 级数据集，必须随条目附带权限申请通道与分步下载指导，防止用户直接全量拉取造成网络与磁盘阻塞。
